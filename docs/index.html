The Generic Go Microservice Engine

hexa-go is no longer just a boilerplate—it's an extensible framework. Optimized for Hexagonal Architecture, it now features surgical AST manipulation, swappable core libraries, and a dynamic blueprint system.

Surgical AST Wiring

Uses Go's Abstract Syntax Tree to inject code without string markers, ensuring 100% reliable modifications.

Library Agnostic

Abstractions for Logger, DB, and Transport. Swap Echo for Gin or GORM for sqlc with zero logic changes.

Blueprint Driven

Templates are external and configurable. Define your own architecture patterns via YAML.

Surgical AST Injection

Forget fragile string replacements. hexa-go parses your source code into an Abstract Syntax Tree to perform surgical modifications at the node level.

How it Works

The CLI locates specific markers (which are now comment nodes in the AST) and inserts new nodes (struct fields, imports, statements) relative to them.

// internal/utils/ast_utils.go
func AddStructField(filePath, structName, fieldName, fieldType, tag string) error {
    fset := token.NewFileSet()
    f, _ := parser.ParseFile(fset, filePath, nil, parser.ParseComments)
    
    ast.Inspect(f, func(n ast.Node) bool {
        ts, ok := n.(*ast.TypeSpec)
        if !ok || ts.Name.Name != structName { return true }
        st, _ := ts.Type.(*ast.StructType)
        
        // Surgical Insert
        newField := &ast.Field{
            Names: []*ast.Ident{ast.NewIdent(fieldName)},
            Type:  ast.NewIdent(fieldType),
        }
        st.Fields.List = append(st.Fields.List, newField)
        return false
    })
    return saveAST(filePath, fset, f)
}
Intelligence: The AST engine automatically handles import deduplication and preserves your code's formatting and comments.

Blueprint System

The entire generation logic is now driven by a dynamic Blueprint. This separates the "What to build" from the "How to build".

Schema Definition

Define your project structure in blueprint.yaml. Map templates to target paths and use dynamic placeholders.

# templates/blueprint.yaml
name: "Standard Hexagonal"
version: "1.0.0"
templates:
  - name: "module_model"
    source: "modules/model.go.tmpl"
    target: "internal/modules/{{.PackageName}}/model.go"
  - name: "core_repository"
    source: "core/repository.go.tmpl"
    target: "repository/{{.ToLower .Name}}.go"

pre_generate:
  - "echo 'Starting generation...'"
post_generate:
  - "go mod tidy"
External Overrides: Simply place a templates/ folder in your current directory to override the embedded defaults.

Core SDK Abstractions

Stop being locked into specific libraries. hexa-go uses Generic Interfaces for all core infrastructure components.

Transport Abstraction (Echo/Gin)

// internal/pkg/interfaces/transport.go
type Context interface {
    Bind(i interface{}) error
    JSON(code int, i interface{}) error
    Param(name string) string
}

// Your business logic only knows about the interface!
func (h *Handler) Create(c interfaces.Context) error { ... }

Database Abstraction (GORM/SQLC)

// internal/pkg/interfaces/database.go
type Database interface {
    Create(ctx context.Context, value interface{}) error
    Find(ctx context.Context, dest interface{}, conds ...interface{}) error
}
Swappable: Switch from Echo to Gin just by providing a different wrapper implementation. No changes needed in your modules/.

Hooks & Plugins

Extend the framework's lifecycle with custom logic.

Generation Hooks

  • Pre-Generate: Run linter, check environment, or pre-fetch dependencies.
  • Post-Generate: Format code, run migrations, or notify webhooks.

Go Plugins

Drop a .go file into the plugins/ directory. Hexa-Go will automatically discover and execute it during generation.

Getting Started

Launch your production project in three commands.

# 1. Install CLI
go install github.com/erwinhermantodev/hexa-go@latest

# 2. Generate Project
hexa-go generate my-app --module github.com/user/my-app

# 3. Initialize & Run
cd my-app && go mod tidy && go run main.go

Directory Structure

The refined layout of a Generic Hexa-Go project.

├── internal/
│ ├── pkg/ // Core SDK Abstractions
│ │ ├── interfaces/ // Logger, DB, Transport interfaces
│ │ ├── logger/ // ZeroLog implementation
│ │ ├── database/ // GORM implementation
│ │ └── transport/ // Echo implementation
│ ├── modules/ // Feature-based co-located modules
├── templates/ // External Blueprints & .tmpl files
├── plugins/ // Custom Go generation plugins
├── blueprint.yaml // Dynamic mapping definition
└── main.go // Abstraction-friendly entry point

Observability

Equip your services with enterprise-grade logging and shutdown mechanics.

Graceful Shutdown Workflow

  1. App receives SIGTERM (e.g., from Kubernetes).
  2. All new HTTP requests are rejected.
  3. Active requests are given 10 seconds to finish.
  4. Database connections are closed safely via the Database Abstraction.
  5. Process exits with code 0.

CI/CD & Deployment

Deploy with confidence using our pre-configured pipelines and Docker optimization.

Multi-Stage Dockerfile

# Builder Stage
FROM golang:1.21-alpine AS builder
...
RUN go build -ldflags="-w -s" -o main .

# Final Stage (Minimal Image)
FROM alpine:3.18
COPY --from=builder /app/main .
CMD ["./main"]
Deployment Tip: The generated Docker image is typically < 25MB, ideal for fast cold starts in Serverless or Kubernetes environments.
